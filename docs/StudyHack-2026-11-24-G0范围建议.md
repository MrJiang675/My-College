# StudyHack · 2026-11-24 G0 范围建议

> **历史候选，已被 2026-11-25 计划版 v3.1 取代。** 当前 G0 已收敛为“登录 → 群组列表 → 创建小组 → 刷新可见 → 重新登录”，QA 仅在依赖就绪时追加，上传不纳入 G0。当前排期与分工以 [StudyHack 计划版](./StudyHack-计划版.md) 和 [StudyHack 待办清单](./StudyHack-待办清单.md) 为准；下文保留 11/24 的候选论证，不再作为当前执行范围。

> 11/24 当时状态：用户已选择候选方案，尚未冻结。最终冻结前必须在 11/25 用真实服务器依赖与 Sites Origin 跑通；本文不把本地静态检查写成联调通过。

## 1. 已确认的产品边界

- 登录后必须读取至少一项真实业务数据。
- 至少完成一条真实业务操作，不能用静态页或假数据替代。
- 普通 `USER` 体验账号与管理员分离；登录、退出、手动 refresh、最小对象权限属于必验项。
- 上传只评估后端直传、已经验证且不超过 10MB 的样例；不承诺分片、断点续传或 256MB。
- 两门课程、课程导师、自动就绪、评测、监控备份、容器化、hash 路由和后端重写均不在本次范围。

## 2. 用户选择

2026-11-24，用户在三个候选中选择了 **“QA + ≤10MB 直传”**。

选择理由：它同时覆盖真实资料读取、上传写入和知识问答，比赛演示价值最高；相应代价是必须同时确认 MinIO、Elasticsearch、PostgreSQL/pgvector 与模型服务，且当前前端尚未实现自动就绪，因此这是高风险候选，不是已通过范围。

## 3. 候选验收路径

1. 使用受控普通 `USER` 账号登录，不使用 dev 管理员。
2. 读取当前账号有权限的真实群组、文档列表或 QA 历史。
3. 在该用户有 OWNER 权限的群组上传一个已授权的文本样例，文件不超过 10MB，走后端直传。
4. 刷新或重新查询文档状态，确认 `PROCESSING/PENDING → READY/FAILED` 可解释；失败不伪装成功。自动轮询不属于本范围。
5. 文档 `READY` 后，在该群组发起 QA 问答，确认真实检索、回答、引用/证据和失败提示；流式行为按现有实现验证。
6. 刷新页面或手动 refresh，确认登录与 QA 历史可恢复。
7. 使用第二个普通账号替换群组、文档、上传会话或 QA 记录 ID，确认不能越权读取、修改或删除。

## 4. 冻结前置条件

以下条件全部有真实证据后，才可把本候选冻结为 11/26 G0 范围：

- 实际 Qoder Sites Origin、公网 HTTPS API 地址与体验账号已确认。
- PostgreSQL/pgvector、MinIO、Elasticsearch 和模型服务连通，模型额度可用。
- 10MB 边界、支持格式、READY/FAILED 状态与至少一个真实样例通过。
- CORS 预检、登录、PATCH、错误响应、Refresh Cookie 和手动 refresh 通过真实浏览器验证。
- QA 问答及引用来自真实检索；上传失败和模型失败均有可读提示。

2026-11-24 晚间新增证据：Sites Origin 已提供为 `https://argus-insights-6ymqxlsdfpp.qoder.website/`；服务器 `106.14.125.122` 的 PostgreSQL 5432 TCP 可达、ES 9200 为 yellow、MinIO 9000/9001 正常；80、443、10001、18080 不可达。体验账号和模型调用由用户人工验收。因此 Origin 已确认，但公网 HTTPS API、真实 CORS/Cookie、10MB 上传和 QA 仍未通过，G0 保持未冻结。

## 5. 不在本候选内的能力

- Assistant 会话与 Assistant 深链路。
- 第二门课程、课程导师卡片和教学策略。
- 前端分片编排、哈希、断点续传、合并恢复。
- 文档状态自动跟踪与完整 ETL 重启恢复。
- 文献卡、练习评测、监控备份、完整容器化和公网开放写入。

## 6. 降级规则

若 MinIO、Elasticsearch、模型额度或 10MB 样例在 11/25 未通过，不擅自改成 QA-only；应把失败证据和“退回仅 QA 问答”的选项提交用户确认。任何核心依赖缺失时，G0 标记未通过或高风险，不用假数据补足。
