## 1. 产品定位与比赛范围

### 1.1 一句话定位

**把大学课程资料和专业文献，变成可引用、可追问、会引导学习的 AI 导师。**

### 1.2 目标用户与真实痛点

- 课程讲义、教材节选和文献分散，学生难以快速定位重点。
- 看懂资料不等于会应用，学生需要分步提示和练习反馈。
- 通用 AI 可能脱离课程内容作答，学生需要可追溯的依据。
- 文献阅读耗时，学生需要研究问题、方法、结论和局限的结构化整理。

### 1.3 完整交付版本（MVP，非 G0）

> 本节是 11 月 27 日后的完整交付范围，不是 25—26 日最小体验门禁；G0 只看第 1.6 节的基础群组保底链路。

1. 两个课程样板，例如计算机专业《数据结构》、电气专业《电路基础》。
2. 每门课程 3—5 份有权使用的资料，提前完成解析入库。
3. 学生选择课程导师后，自动进入对应知识库。
4. 支持概念讲解、引导解题、练习反馈三种基本教学方式。
5. 回答展示引用；证据不足时明确拒答或说明缺口。
6. 上传后自动显示处理状态，无需手动刷新。
7. 登录、历史记录、流式输出和引用查看在公网完整可用。
8. 提供 2—3 分钟演示和真实评测结果。

### 1.4 本周明确不做

- 多模型自选、大规模模型供应商替换。
- 复杂 OCR、公式识别、复杂表格还原。
- 多论文矩阵、自动综述、完整科研写作流水线。
- 多 Agent、复杂工作流、完整学习画像和错题本。
- 为比赛另建学校/学院/专业组织系统。
- 把后端重写为 Node/Supabase。

> 不同专业先通过“课程知识库 + 导师配置 + 教学指令”区分，不需要分别训练模型。

## 4. 架构与发布门禁

### 4.1 部署架构

```text
评委/学生浏览器
  │ HTTPS
  ▼
Qoder Sites（Vue 静态产物 Argus-frontend/dist，更新现有站点并启用 SPA）
  │ 跨域 HTTPS + Cookie
  ▼

  ▼
Spring Boot 后端（只监听回环或受控内网）
  ├── PostgreSQL / pgvector
  ├── Elasticsearch
  ├── 对象存储
  └── 对话与向量模型服务
```

- Qoder Sites 负责前端静态托管，不迁移 Java 后端；Nginx 根路径不提供 SPA，只反代 `/api/` 到 Spring。
- 当前发布从 `Argus-replica` 根目录执行，静态目录为 `Argus-frontend/dist`，启用 SPA，更新现有站点，不新建站点；根目录 `.Argus 数据洞察中心.qoder.site` 为准，前端目录内描述文件是旧快照，均不得手改或删除。
- API 地址通过 `VITE_API_BASE_URL` 在构建时注入为 `https://106.14.125.122/api`；改地址或产物后必须重新构建发布。
- **G0 最小体验**允许“已构建 JAR + 服务器现有依赖服务 + HTTPS 反向代理”的轻量运行方式，不要求当天完成容器化、自启、监控和备份。

- 数据库、索引、对象存储和管理端口不得直接暴露公网。
- G0 可以先让非开发机验收人（待确认）访问现有私有/受限 Sites 链接；陌生人公开访问是后续门禁。站点访问与 Argus 业务登录是两层权限。
