## 1. 目标、完成定义与人员

### 1.1 最小体验目标（G0，争取 11 月 25 日晚完成）

由非开发机验收人（待确认，不默认由组员甲承担）打开已发布的 Qoder Sites 链接，在其非开发机、独立网络环境下：

> 打开项目 → 请求到达公网 HTTPS API → 连接服务器上已启动的后端 JAR → 登录 → 完成一条真实基础业务链路。

通过 G0 必须同时满足：

- Sites 已发布；当前必须从 `Argus-replica` 根目录使用 `.Argus 数据洞察中心.qoder.site`，以 `Argus-frontend/dist` 更新现有站点并启用 SPA。`Argus-frontend` 内描述文件是旧快照，不手改或删除，也不据此新建站点。
- 浏览器 Network 中业务请求到达 `https://106.14.125.122/api`，不指向 `localhost`、`127.0.0.1`、旧 API 域名或我的开发机。
- 服务器运行已构建 JAR，不依赖现场 Maven 编译、源码目录或我的本地进程。
- 登录、退出、刷新/refresh 和最小权限检查通过。
- 完成下方“基础保底链路”；QA 冲刺链路通过时额外记录，不阻塞基础保底。
- 遗留问题按影响记录；核心阻断未解决时明确标记 G0 未通过。

**基础保底链路（不依赖模型/MinIO/ES）**：注册或登录 → 进入“协作小组” → 读取真实群组列表 → 创建一个小组 → 刷新页面仍可见 → 退出并重新登录。该链路只依赖 PostgreSQL 与认证，用于先证明 Sites、HTTPS、JAR、CORS、Cookie 和真实数据库已联通。

**QA 冲刺链路（模型/ES/样板数据就绪时）**：进入已有小组 → 知识库问答 → 提问 → SSE 逐段返回 → 展示真实引用 → 刷新后查看历史。若模型 Key、ES 或样板资料未就绪，保留为 11 月 26—27 日联调项，不用假数据替代。

**G0 不要求**：上传、大文件分片、自动就绪、Assistant 深链路、两门课程、完整课程导师、文献卡、评测、监控备份、完整容器化、陌生人公开访问。11 月 25—26 日不先改这些功能。
